You already have a design system written down in your Panda config: every color, space, font, radius, and shadow.
Describing the system was never the hard part. Seeing it was.

![Studio, a full color system rendered from your Panda config](/blog/spec-studio-hero.png)

Studio shows it. Run one command in your project:

```bash
pnpm panda studio
```

It opens [studio.panda-css.com](https://studio.panda-css.com/) connected to a local server, and updates as you save.
Colors become a swatch grid, spacing becomes a sorted scale, fonts become specimens. Nothing from your project is
uploaded.

## Your tokens, laid out

Every token category gets a layout that fits it. Colors with a `_dark` value show both side by side. Click a token to
copy its name.

![Font sizes in Studio: a type specimen for every step, with rem and px values](/blog/spec-studio-tokens.png)

Press `⌘K` to search the whole system: tokens, values, references, recipes, patterns, conditions, and themes. Pick a
token and Studio opens it. If you have more than one [theme](/docs/theming/multiple-themes), pick one from the **Theme**
menu to see only the tokens it overrides.

## Which tokens are you actually using?

Every design system collects tokens nobody references. A `red.500` that got replaced, a spacing step added for one
screen and never touched again. You can't spot them in the config, because a used token and an unused one look identical
there.

Switch to **Usage** and the project scan answers it. Per category, it shows how many tokens your code uses, which ones
nothing uses, and every hard-coded value with the files it's in. Read the unused list first. Those are the tokens you
can delete.

![The project scan from panda studio: tokens used, coverage per category, and hard-coded values by file](/blog/spec-studio-analyze.png)

Click a file to see its code next to its issues. Usage is counted the same way as
[`panda analyze`](/docs/design-systems/analyze), by the same Rust compiler we
[shipped in Panda 2.0](/blog/panda-css-v2).

The **Playground** does the same check one object at a time. Type a `css({ ... })` object and it flags any value that
isn't a token as you write it.

## Open a spec file without the CLI

You can still open Studio on its own. Run `panda codegen --spec` and drop the file it writes on
[studio.panda-css.com](https://studio.panda-css.com/):

```
styled-system/specs/design-system.json
```

You can also paste an https link to that file, like a GitHub URL. Studio keeps it in the address as `#url=`, so if the
file is public, the page itself is a link you can send to a teammate or a designer.

## It's still your data

Studio doesn't replace building your own viewer. The [JSON Spec](/docs/theming/json-spec) docs show you how: every
category is `{ name, value }`, so a color grid is one `.map()`. Studio is the version you don't have to build. See the
[Studio docs](/docs/theming/studio) for every option.
