---
title: Tracking JSX
description: How Panda connects a JSX tag to a config recipe, and what breaks that connection.
---

Config recipes emit CSS for `<Button size="lg" />` only if Panda can treat that tag as the recipe. The match is the
**component name**, not the import. A local function named `Button` is enough, even if it never imported
`styled-system/recipes`.

`cva` and `sva` do not need this. Defining them already emits every variant, so a missed JSX tag does not leave you
without CSS.

This page is the extract rule for **tag names**. Prop names and runtime values are
[Extraction rules](/docs/styling/extraction-rules). If you are shipping a library and renaming wrappers, also read
[Track usage in wrapped components](/docs/design-systems/track-usage).

## Theme key, className, and JSX name

A config recipe has three names. Mixing them up is the usual reason tracking fails.

```ts
// theme key: "button"  →  import { button }, type ButtonVariant
export const buttonRecipe = defineRecipe({
  className: 'btn', // CSS stem only: .btn, .btn--size_sm
  jsx: ['Button'] // tags extract should treat as this recipe
})
```

| Name        | Comes from                       | Used for                                             |
| ----------- | -------------------------------- | ---------------------------------------------------- |
| Theme key   | `theme.recipes.button`           | Import, extract name, types (`ButtonVariant`)        |
| `className` | Recipe config                    | CSS stem. Falls back to the theme key if you omit it |
| JSX name    | `jsx`, or `capitalize(themeKey)` | `<Button>` tracking                                  |

If you set `className: 'btn'` and leave `jsx` off, you still `import { button }`, the classes become `btn` and
`btn--size_sm`, and JSX tracking still looks for `<Button>`.

## Default JSX names

For `theme.recipes.button`, the default tag is `Button`.

For `theme.slotRecipes.card`, Panda also tracks `Card.Header`, `CardHeader`, and the other `{Name}.{Slot}` /
`{Name}{Slot}` forms. Those suffixes are built from the **theme key**, not from `className`. If the recipe has no `root`
slot, `Card.Root` and `CardRoot` are tracked too.

The **exported** compound name still has to match. `Card` works. `Panel` does not, unless you set `jsx`.

```tsx
const { withProvider, withContext } = createSlotRecipeContext(card)

export const Card = {
  Root: withProvider('div', 'root'),
  Header: withContext('header', 'header')
}
```

## Custom names

```ts
export const buttonRecipe = defineRecipe({
  className: 'button',
  jsx: ['Button', 'LinkButton', /Btn$/]
})
```

Strings are exact tags. A regex matches the full tag, including `Button.Root`.

<Callout type="warning">
  `jsx` **replaces** the default root name. It does not add to it. If you set `jsx: ['LinkButton']` and omit
  `Button`, `<Button>` is no longer tracked.
</Callout>

On a slot recipe, `jsx` replaces the root name only. Slot compounds stay `{ThemeKey}.{Slot}` and `{ThemeKey}{Slot}`.

```ts
export const cardRecipe = defineSlotRecipe({
  className: 'card',
  slots: ['root', 'header'],
  jsx: ['Panel']
})
```

That tracks `<Panel>`, `<Card.Root>`, and `<Card.Header>`. It does **not** track `<Card>`, `<Panel.Root>`, or
`<Panel.Header>`.

If you export `Panel = { Root, Header }`, list the tags you actually render, or use a regex:

```ts
jsx: ['Panel', 'Panel.Root', 'Panel.Header']
// or
jsx: [/^Panel/]
```

Keep `Card` / `Card.Root` in that list if those tags still appear in the app.

## Wrappers

Always split variant props off before you spread onto the DOM. Otherwise `onClick` can emit a junk class like
`button--onClick_…`.

```tsx
export function Button(props: ButtonProps) {
  const [variants, rest] = button.splitVariantProps(props)
  return <button {...rest} className={cx(button(variants), props.className)} />
}
```

Two things extract cannot follow, even when the runtime call is correct:

```tsx
// renamed prop: extract cannot see that buttonSize is size
export function Button({ buttonSize, children }) {
  return <button className={button({ size: buttonSize })}>{children}</button>
}

// wrapper name is not the recipe name
export function Random(props) {
  return <button className={button(props)} />
}
```

`Random` needs `jsx: ['Random']`, or an export named `Button`. Direct literal calls like `button({ size: 'lg' })` are
extracted either way. Dynamic values still need [`staticCss`](/docs/recipes/dynamic-variants).

The flip side: a local `<Button>` that is **not** this recipe can still be treated as one. The match is not
import-gated.
