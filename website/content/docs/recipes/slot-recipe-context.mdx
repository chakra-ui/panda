---
title: Slot recipe context
description: Distribute a slot recipe across a compound component tree. The tool for wrapping Ark UI, Radix, and Base UI.
---

A slot recipe returns a map of classes. `createSlotRecipeContext` turns that map into compound components: the root
takes variant props, and the parts pick up their slot styles from context. That is how you wrap Ark UI, Radix, or
Base UI without asking every consumer to know which class goes on which part.

<Callout type="info">
  You need [`jsxFramework`](/docs/reference/config#jsxframework) in your config, or `styled-system/jsx` is not
  generated. This helper is a Client Component (`"use client"`).
</Callout>

It works with [`sva`](/docs/recipes/slot-recipes) or
[`defineSlotRecipe`](/docs/recipes/config-recipe#config-slot-recipe).

```tsx
import { sva } from '../styled-system/css'
import { createSlotRecipeContext } from '../styled-system/jsx'

const card = sva({
  slots: ['root', 'title', 'body'],
  base: {
    root: { rounded: 'lg', borderWidth: '1px', p: '4' },
    title: { fontWeight: 'semibold' },
    body: { color: 'gray.600', fontSize: 'sm' }
  },
  variants: {
    size: {
      sm: { root: { p: '3' } },
      lg: { root: { p: '6' } }
    }
  },
  defaultVariants: { size: 'sm' }
})

const { withProvider, withContext } = createSlotRecipeContext(card)

export const Card = {
  Root: withProvider('div', 'root'),
  Title: withContext('h2', 'title'),
  Body: withContext('div', 'body')
}
```

`size` is set once on the root. Title and body read their classes from context.

```tsx
<Card.Root size="lg">
  <Card.Title>Hello</Card.Title>
  <Card.Body>A card with parts.</Card.Body>
</Card.Root>
```

A config slot recipe is the same call with a different import:

```tsx
import { card } from '../styled-system/recipes'
import { createSlotRecipeContext } from '../styled-system/jsx'

const { withProvider, withContext } = createSlotRecipeContext(card)
```

## withRootProvider

Use this when the root **does not render a DOM element**. Some headless `Root` components are context-only. This
helper provides the slot map and does not apply a slot class.

```tsx
import { Dialog } from '@ark-ui/react'

const DialogRoot = withRootProvider(Dialog.Root, {
  defaultProps: { lazyMount: true }
})
```

The only option is `defaultProps`. There is no slot to style, so `unstyled` and factory options do not apply.

## withProvider

Use this when the root **renders an element**. It splits variant props, provides the slot map, styles that slot, and
sets `data-slot` to the slot name.

```tsx
import { Avatar } from '@ark-ui/react'

const AvatarRoot = withProvider(Avatar.Root, 'root')
```

The second argument is the slot name. The third is factory options:
[`defaultProps`](#default-props), [`forwardProps`](#forwarding-props), `shouldForwardProp`, `dataAttr`.

## withContext

Consumes context and applies one slot. It does not accept variant props. Those already live on the provider.

```tsx
const AvatarImage = withContext(Avatar.Image, 'image')
const AvatarFallback = withContext(Avatar.Fallback, 'fallback')
```

Same factory options as `withProvider`. Each part also gets `data-slot`.

<Callout type="warning">
  A `withContext` part throws if it renders outside its provider. Keep the tree under the matching
  `withProvider` or `withRootProvider`.
</Callout>

## unstyled

Skip **this element's** slot styles. Style props, `css`, and `className` still apply. The slot map in context does
not change, so children keep their styles unless they pass `unstyled` too.

```tsx
<AvatarRoot unstyled>
  <AvatarImage />
</AvatarRoot>
```

The root has no recipe class. The image still looks like the recipe.

```tsx
<AvatarRoot>
  <AvatarImage unstyled css={{ bg: 'red.500' }} />
</AvatarRoot>
```

To strip every part, pass `unstyled` on each one you wrap.

<Callout type="info">
  `withRootProvider` does not style an element, so `unstyled` there does nothing. Put it on the parts.
</Callout>

## Default props

Use `defaultProps` for HTML or component props. Incoming props win.

```tsx
const CardHeader = withContext('header', 'header', {
  defaultProps: { role: 'banner' }
})
```

Do not put variant keys here. `withProvider` splits variants off the incoming props only, so
`defaultProps: { size: 'sm' }` does not pick the recipe. Set variant defaults on the recipe's `defaultVariants`.

## Forwarding props

`withProvider` uses variant props to pick styles, then drops them so they do not land on the DOM. List a key in
`forwardProps` when the wrapped component still needs the value, for example to mirror `orientation` as
`aria-orientation`.

```tsx
function TabsRoot({ orientation, ...rest }: TabsRootProps) {
  return <div aria-orientation={orientation} {...rest} />
}

export const Tabs = withProvider(TabsRoot, 'root', {
  forwardProps: ['orientation']
})
```

`withContext` has no variants to split. Its `forwardProps` is the
[factory](/docs/styling/style-props#factory-options) allowlist: keep a prop that shares a name with a CSS property
from becoming a style.

```tsx
const TabIndicator = withContext(Indicator, 'indicator', {
  forwardProps: ['width']
})
```

Without that, `width` would be treated as a style prop.

## Naming config recipes

The exported name must match the recipe (`Card` for theme key `card`), or you list it in `jsx`. Nested `Card.Root`
and `CardRoot` are tracked from the **theme key**, not from a custom `jsx` string. The full rule is on
[Tracking JSX](/docs/recipes/jsx-tracking).

## How styles apply

A config slot recipe sets `className` to `cx(slotClass, rest.className)`.

An `sva` recipe depends on [`jsxStyleProps`](/docs/reference/config#jsxstyleprops). `'all'` spreads the slot's style
object as style props. `'minimal'` uses `css.raw`. `'none'` uses `cx(css(slotStyles), className)`.
