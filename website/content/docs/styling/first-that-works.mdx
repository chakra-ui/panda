title: Value Fallbacks
description:
  Ship a modern CSS value with a fallback for browsers that don't support it yet. firstThatWorks() emits both
  declarations in the order CSS needs.
---

## Why you need it

Browsers don't all understand the same values. `100dvh` sizes to the visible viewport on mobile, but Safari before 15.4
has never heard of it. `oklch()` picks colors outside sRGB, but a two-year-old Chrome drops the declaration. Every new
value goes through this window where some of your users have it and some don't.

CSS handles it with a fallback: declare the property twice. A browser that can't parse the second value keeps the first,
and a browser that can uses it.

```css
.hero {
  min-height: 100vh;
  min-height: 100dvh;
}
```

Panda couldn't write that, because an array already means responsive values. `firstThatWorks()` fills the gap. List the
values you'd accept, the one you want first, and Panda emits one declaration per value in reverse, so each browser keeps
the first one it supports.

```ts
import { css, firstThatWorks } from 'styled-system/css'

css({ minHeight: firstThatWorks('100dvh', '100vh') })
```

```css
.min-h_firstThatWorks\(100dvh\,_100vh\) {
  min-height: 100vh;
  min-height: 100dvh;
}
```

Write the value you want first, the same way you'd write `var(--brand, red)`. Two values minimum, because one has
nothing to fall back to. Three or more work the same way, most preferred first.

## Common patterns

Wide-gamut color with an sRGB fallback:

```ts
css({ color: firstThatWorks('oklch(55% 0.18 250)', '#0057b8') })
```

Vendor-prefixed values, where each browser keeps the spelling it knows:

```ts
css({ position: firstThatWorks('sticky', '-webkit-sticky', 'relative') })
```

A newer sizing keyword behind the one every browser has:

```ts
css({ width: firstThatWorks('fit-content', '-moz-fit-content', 'auto') })
```

Color mixing that falls back to a token:

```ts
css({ bg: firstThatWorks('color-mix(in oklch, brand, white 20%)', 'brand.light') })
```

That last one shows each member going through the same pipeline as a standalone value. Tokens, shorthands, and default
units resolve per member:

```css
.bg_firstThatWorks\(color-mix\(in_oklch\,_brand\,_white_20\%\)\,_brand\.light\) {
  background-color: var(--colors-brand-light);
  background-color: color-mix(in oklch, var(--colors-brand), white 20%);
}
```

The call folds at build time. With [source transforms](/docs/styling/source-transforms) on, a static call inlines to its
value and the import is dropped.

## Where it works

Anywhere a value goes: nested conditions, responsive arrays, recipes, slot recipes, and JSX style props.

```tsx
import { css, cva, firstThatWorks } from 'styled-system/css'
import { styled } from 'styled-system/jsx'

css({
  _hover: { color: firstThatWorks('oklch(60% 0.2 30)', 'red') },
  height: [firstThatWorks('100dvh', '100vh'), 'auto']
})

const hero = cva({
  base: { minHeight: firstThatWorks('100svh', '100vh') }
})

<styled.div color={firstThatWorks('color(display-p3 1 0 0)', 'red')} />
```

## Config recipes

A config file loads before `styled-system/css` exists. Import the same helper from `@pandacss/dev`:

```ts filename="panda.config.ts"
import { defineRecipe, firstThatWorks } from '@pandacss/dev'

export const card = defineRecipe({
  className: 'card',
  base: { color: firstThatWorks('oklch(45% 0.16 250)', '{colors.blue.700}') }
})
```

Or write the value form directly. `firstThatWorks()` returns a plain string, and the string is what Panda reads:

```ts
base: {
  color: 'firstThatWorks(oklch(45% 0.16 250), {colors.blue.700})'
}
```

## Members are typed by the property

Inside `firstThatWorks(` you get the property's own values: the color tokens `color:` offers, the keywords `position:`
offers. Under `strictTokens`, each member is checked on its own:

```ts
css({ color: firstThatWorks('blue.300', 'red.200') }) // ok
css({ color: firstThatWorks('blue.300', 'notAToken') }) // error: not a color token
css({ padding: firstThatWorks('[1rem]', '4') }) // the escape hatch applies per member
```

Members can differ in type. `firstThatWorks('1rem', 4)` is fine.

## `!important`

Mark the whole run, not a member:

```ts
css({ color: 'firstThatWorks(oklch(60% 0.2 30), red) !important' })
```

Marking only some members is rejected and emits nothing. An important declaration wins whatever its position, so the
others could never apply.

## What a fallback can't recover

A fallback works because the browser discards a declaration it can't parse. It does not restart the cascade when a value
fails later. `var(--maybe-invalid)` parses fine and only fails at computed-value time, so a fallback behind it never
applies. For a variable, use CSS's own fallback, `var(--accent, #0057b8)`. For the same reason, a custom-property
declaration such as `'--accent': firstThatWorks(...)` is refused with a warning.

`@supports` is still the tool when more than one property has to change together, or when the fallback is a different
property altogether.

## When nothing is emitted

`firstThatWorks(...)` isn't real CSS, so a malformed run emits nothing for that property rather than a broken
declaration. Each case is reported in the build:

- fewer than two values (`first_that_works_arity_invalid`)
- an object, array, boolean, or null member (`first_that_works_member_invalid`)
- unbalanced brackets or quotes (`first_that_works_unbalanced`)
- a run nested in a run (`first_that_works_nested`)
- `!important` on only some members (`first_that_works_importance_mixed`)
- a custom property (`first_that_works_custom_property`, a warning)

A dynamic member isn't a mistake. It's handled like any other [dynamic style](/docs/styling/dynamic-styling).
