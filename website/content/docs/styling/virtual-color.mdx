---
title: Virtual Color
description: Panda allows you to create a virtual color or color placeholder in your project.
---

The `colorPalette` property is how you create virtual colors.

```js
import { css } from '../styled-system/css'

const className = css({
  colorPalette: 'blue',
  bg: 'colorPalette.100',
  _hover: {
    bg: 'colorPalette.200'
  }
})
```

This will translate to the `blue.100` background color and `blue.200` background color on hover.

Virtual colors are useful when creating easily customizable components.

## Using opacity modifier

See [using a custom property](/docs/styling/color-opacity-modifier#using-a-custom-property) for the
`{colors.colorPalette…/opacity}` syntax on `--*` variables:

```js
import { css } from '../styled-system/css'

const className = css({
  colorPalette: 'blue',
  '--tint': '{colors.colorPalette.500/50}',
  bg: 'var(--tint)',
  color: 'colorPalette.700'
})
```

## Using with recipes

You can also use virtual colors with recipes.

```js
import { css, cva, cx } from '../styled-system/css'

const button = cva({
  base: {
    padding: 4
    // you can also specify a default colorPalette in the `base` recipe key
    // colorPalette: 'blue',
    // ^^^^^^^^^^^^^^^^^^^^
  },
  variants: {
    variant: {
      primary: { color: 'colorPalette.500' }
    }
  },
  defaultVariants: { variant: 'primary' }
})
```

## Using with different color modes

You can also use virtual colors with different conditions, such as color modes.

```js
import { css, cva, cx } from '../styled-system/css'

const someButton = cva({
  base: { padding: 4 },
  variants: {
    variant: {
      primary: {
        bg: { base: 'colorPalette.500', _dark: 'colorPalette.200' },
        color: { base: 'white', _dark: 'gray.900' }
      }
    }
  },
  defaultVariants: { variant: 'primary' }
})

export const App = () => {
  return (
    <>
      <div className="light">
        <button className={cx(css({ colorPalette: 'blue' }), someButton())}>Click me</button>
        <button className={cx(css({ colorPalette: 'green' }), someButton())}>Click me</button>
        <button className={cx(css({ colorPalette: 'red' }), someButton())}>Click me</button>
      </div>
      <div className="dark">
        <button className={cx(css({ colorPalette: 'blue' }), someButton())}>Click me</button>
        <button className={cx(css({ colorPalette: 'green' }), someButton())}>Click me</button>
        <button className={cx(css({ colorPalette: 'red' }), someButton())}>Click me</button>
      </div>
    </>
  )
}
```

## Semantic Virtual Colors

Semantic virtual colors gives you an ability to create a virtual color organized by category, variant and state.
Hierarchically organized virtual colors are useful when creating easily customizable components.

```js
const theme = {
  extend: {
    semanticTokens: {
      colors: {
        button: {
          dark: {
            value: 'navy'
          },
          light: {
            DEFAULT: {
              value: 'skyblue'
            },
            accent: {
              DEFAULT: {
                value: 'cyan'
              },
              secondary: {
                value: 'blue'
              }
            }
          }
        }
      }
    }
  }
}
```

You can now use the root `button` color palette and its values directly:

```tsx
import { css } from '../styled-system/css'

export const App = () => {
  return (
    <button
      className={css({
        colorPalette: 'button',
        color: 'colorPalette.light',
        backgroundColor: 'colorPalette.dark',
        _hover: {
          color: 'colorPalette.light.accent',
          background: 'colorPalette.light.accent.secondary'
        }
      })}
    >
      Root color palette
    </button>
  )
}
```

Or you can use any deeply nested property (e.g. `button.light.accent`) as a root color palette:

```tsx
import { css } from '../styled-system/css'

export const App = () => {
  return (
    <button
      className={css({
        colorPalette: 'button.light.accent',
        color: 'colorPalette.secondary'
      })}
    >
      Nested color palette leaf
    </button>
  )
}
```

> **Note**: Nested tokens require glob patterns in the `colorPalette` config (e.g., `'button.*'`) to generate proper CSS
> variables.

## Pregenerated Virtual Colors

Use the `staticCss` option in the config to pre-generate values for the `colorPalette` property.

This is useful when you want to use a color palette that can be changed at runtime (e.g. in Storybook knobs).

> Learn more about [static css generation](/docs/styling/static).

```tsx
export default defineConfig({
  staticCss: {
    css: [
      {
        properties: { colorPalette: ['red', 'blue'] }
      }
    ]
  }
})
```

Then in your code, you can design components that use the `colorPalette` property:

```tsx
import { css } from '../styled-system/css'

function ButtonShowcase() {
  const [colorPalette, setColorPalette] = useState('red')
  return (
    <div>
      <select value={colorPalette} onChange={e => setColorPalette(e.currentTarget.value)}>
        <option value="red">Red</option>
        <option value="blue">Blue</option>
      </select>

      <button
        className={css({
          bg: 'colorPalette.50',
          color: 'colorPalette.500',
          colorPalette
        })}
      >
        Click me
      </button>
    </div>
  )
}
```

## Configuration

By default, every color group in your theme is a palette. The examples below use this theme:

```ts filename="panda.config.ts"
import { defineConfig } from '@pandacss/dev'

export default defineConfig({
  theme: {
    semanticTokens: {
      colors: {
        gray: {
          1: { value: '#fcfcfc' },
          9: { value: '#8d8d8d' },
          solid: {
            bg: { value: '{colors.gray.9}' },
            fg: { value: 'white' }
          }
        },
        blue: {
          1: { value: '#fbfdff' },
          9: { value: '#0090ff' },
          solid: {
            bg: { value: '{colors.blue.9}' },
            fg: { value: 'white' }
          }
        }
      }
    }
  }
})
```

It produces four palettes. A palette maps every token below it to a virtual `colorPalette.*` token:

- `gray` and `blue`: `colorPalette.1`, `colorPalette.9`, `colorPalette.solid.bg`, `colorPalette.solid.fg`
- `gray.solid` and `blue.solid`: `colorPalette.bg`, `colorPalette.fg`

```tsx
css({ colorPalette: 'blue', bg: 'colorPalette.solid.bg', color: 'colorPalette.solid.fg' })
css({ colorPalette: 'blue.solid', bg: 'colorPalette.bg', color: 'colorPalette.fg' })
```

Use the `colorPalette` property in your theme to choose which palettes are generated.

### Disable Color Palette

To completely disable color palette generation, set `enabled` to `false`:

```ts filename="panda.config.ts"
import { defineConfig } from '@pandacss/dev'

export default defineConfig({
  theme: {
    colorPalette: {
      enabled: false
    }
  }
})
```

### Include Specific Colors

Use `include` to list the palettes you want:

```ts filename="panda.config.ts"
import { defineConfig } from '@pandacss/dev'

export default defineConfig({
  theme: {
    colorPalette: {
      include: ['gray']
    }
  }
})
```

Only `gray` is a palette now, and it keeps all of its tokens, including the nested ones:

```tsx
css({ colorPalette: 'gray', bg: 'colorPalette.solid.bg', color: 'colorPalette.1' })
```

Nested groups are palettes too. Include them with a glob pattern:

```ts filename="panda.config.ts"
import { defineConfig } from '@pandacss/dev'

export default defineConfig({
  theme: {
    colorPalette: {
      include: ['gray.*'] // gray and gray.solid
    }
  }
})
```

### Exclude Specific Colors

Use `exclude` to drop palettes. Excluding a palette also drops its nested groups:

```ts filename="panda.config.ts"
import { defineConfig } from '@pandacss/dev'

export default defineConfig({
  theme: {
    colorPalette: {
      exclude: ['blue'] // gray and gray.solid remain
    }
  }
})
```

`exclude` wins over `include`:

```ts filename="panda.config.ts"
import { defineConfig } from '@pandacss/dev'

export default defineConfig({
  theme: {
    colorPalette: {
      include: ['gray', 'blue'],
      exclude: ['blue'] // only gray
    }
  }
})
```

## Large Nested Themes

Every nested group is a palette, so a theme with many nested groups per color (`gray.solid`, `gray.subtle`,
`gray.surface`, …) can produce hundreds of palette names. With `strictTokens`, that union can make TypeScript report
"Expression produces a union type that is too complex to represent" on components with spread props.

Exclude every nested name to keep only the top-level palettes:

```ts filename="panda.config.ts"
import { defineConfig } from '@pandacss/dev'

export default defineConfig({
  theme: {
    colorPalette: {
      exclude: ['*.*'] // gray and blue, but not gray.solid or blue.solid
    }
  }
})
```

Every virtual token still works through the top-level palette:

```tsx
css({ colorPalette: 'gray', bg: 'colorPalette.solid.bg', color: 'colorPalette.1' })
```
