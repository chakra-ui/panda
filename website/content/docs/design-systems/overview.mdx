## FAQ

<Faq>

<Details>
<summary>Why should my component library use an external styled-system package?</summary>

De-coupling the component library from its `styled-system` means your users share the same runtime code between
your library and their app, instead of bundling two copies of `css()`, `cva()`, and the JSX factory.

```tsx filename="component-lib/src/button.tsx"
import { css } from '@acme-org/styled-system/css'

export function Button({ children, css: cssProp }) {
  return (
    <button type="button" className={css({ bg: 'red.300', px: '2', py: '3' }, cssProp)}>
      {children}
    </button>
  )
}
```

```tsx filename="app/src/App.tsx"
import { Button } from '@acme-org/design-system'
import { css } from '@acme-org/styled-system/css'

export function App() {
  return <Button css={{ color: 'white' }}>Click me</Button>
}
```

Marking the `styled-system` package as external in your build tool keeps that runtime code, the `css` function in
the example above, imported once, not duplicated per package. See
[Set up a library package](/docs/design-systems/setup) for the full setup.

</Details>

<Details>
<summary>How do I use the shared styled-system package day to day?</summary>

Like any other workspace dependency: install it, then set `importMap` in `panda.config.ts` to the same package name
so Panda knows which imports belong to it.

```bash
pnpm add @acme-org/styled-system
```

```tsx filename="panda.config.ts"
import { defineConfig } from '@pandacss/dev'

export default defineConfig({
  //...
  importMap: '@acme-org/styled-system'
})
```

</Details>

<Details>
<summary>How do I override tokens used by the shared package?</summary>

Extend `theme` in your users' own `panda.config.ts`, same as overriding any preset's tokens:

```tsx filename="panda.config.ts"
import { defineConfig } from '@pandacss/dev'

export default defineConfig({
  //...
  presets: ['@acme-org/preset'],
  theme: {
    extend: {
      tokens: {
        colors: { primary: { value: 'blue.500' } }
      }
    }
  }
})
```

See [Theme](/docs/theming/theme) for the full set of things `theme.extend` can override, not just tokens.

</Details>

</Faq>
