---
title: Consume without Panda
description: Ship a stylesheet the app imports. No designSystem, no app tokens.
---

If your app doesn't use Panda, `designSystem` and theme extension aren't available to it at all.

To ship a stylesheet the app imports, run Panda in the library, generate a plain CSS file with `panda cssgen`, and
publish that file next to your components.

## Emit a stylesheet

Run codegen first, then pick how the CSS is shaped.

### Bundled CSS file

Everything in one file. One import for the app, and the least to publish.

```bash
panda codegen
panda cssgen --outfile dist/styles.css
```

```json filename="packages/ds/package.json" {5}
{
  "name": "@acme/ds",
  "exports": {
    ".": "./dist/index.js",
    "./styles.css": "./dist/styles.css"
  },
  "files": ["dist"],
  "scripts": {
    "build": "panda codegen && panda cssgen --outfile dist/styles.css && tsup"
  }
}
```

### Split CSS files

`--splitting` writes one file per layer and one per recipe, so a team can load only the recipes it renders. Pass
`--outdir` to say where they land.

```bash
panda codegen
panda cssgen --splitting --outdir dist/panda
```

```
dist/panda/styles.css                 # layer order, then imports everything below
dist/panda/styles/reset.css
dist/panda/styles/global.css
dist/panda/styles/tokens.css
dist/panda/styles/utilities.css
dist/panda/styles/recipes.css
dist/panda/styles/recipes/button.css  # one per recipe
```

Export the tree rather than a single file:

```json filename="packages/ds/package.json"
{
  "exports": {
    "./styles.css": "./dist/panda/styles.css",
    "./styles/*": "./dist/panda/styles/*"
  }
}
```

The app takes everything, or one recipe:

```ts
import '@acme/ds/styles.css'
import '@acme/ds/styles/recipes/button.css'
```

Only `styles.css` declares the layer order. Import leaves on their own and layers rank by first appearance instead,
which is not the order Panda intends. If you cherry-pick, declare it yourself first:

```css
@layer reset, base, tokens, recipes, utilities;

@import '@acme/ds/styles/recipes/button.css';
```

`panda lib` doesn't write any of these. That command is for apps that consume you through `designSystem`, not a plain
stylesheet. Add the exports yourself.

## Emit every variant

The app never scans your source, so the sheet holds only what the library itself rendered. A recipe your components
never call is left out entirely, and a variant they never pass ships as a class name with no rule behind it.
Pre-generate them:

```ts filename="packages/ds/panda.config.ts"
export default defineConfig({
  staticCss: {
    recipes: { button: ['*'], card: ['*'] }
  }
})
```

`recipes: '*'` covers every recipe and is fine for a stylesheet-only package. List them instead if the same package also
ships for `designSystem` consumers, where the app generates its own CSS and this file is dead weight. See
[Static CSS](/docs/styling/static).

## Import it in the app

The app needs just the CSS file and your components:

```tsx filename="src/main.tsx"
import '@acme/ds/styles.css'
import { Button } from '@acme/ds'

export function App() {
  return <Button>Save</Button>
}
```

```css filename="src/index.css"
@layer reset, base, tokens, recipes, utilities;
```

Declare the layers yourself only if the app also loads other layered CSS of its own. The shipped file already carries
the library's own rules.

## Managing style conflicts

Two independently built stylesheets can emit the exact same class names (`.button`, `--colors-brand`). Set `prefix` in
the library whose styles should yield:

```ts filename="packages/ds/panda.config.ts"
export default defineConfig({
  prefix: 'acme' // .button → .acme-button
})
```

```ts
// also works: hash class names, or move CSS variables under a scoped root
hash: true
cssVarRoot: '#app'
```

Derive the prefix from the package's name and major version. A hardcoded one drifts the moment you forget to bump it.
The full collision model, token scoping, and the limits of `prefix`: [Style isolation](/docs/styling/style-isolation).

## Storybook still runs Panda

Your stories call the same recipes your components do, so Storybook is a Panda consumer even though production only ever
imports `styles.css`. See [Storybook](/docs/design-systems/storybook).

## Example

A Next.js app with no Panda installed at all, just the published CSS and components:

```bash
npx degit chakra-ui/panda-examples/examples/standalone-app my-app
```

[standalone-app](https://github.com/chakra-ui/panda-examples/tree/main/examples/standalone-app) in panda-examples.
